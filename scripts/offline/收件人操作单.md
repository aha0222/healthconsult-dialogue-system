# 收件人操作单 · 成员 B 离线运行时

> 一页看完，照着做就行。预计 **10 分钟**（其中 8 分钟是下模型）。

## 开始前确认两件事

| 前提 | 怎么确认 |
|---|---|
| 装了 **Python 3.12** | `python -V` |
| 仓库**已应用 Day0 契约 stub** | `git pull` 到最新，或确认 `backend/app/config.py` 里有 `offline_mode` 这个字段 |

**第二条为什么重要**：`OFFLINE_MODE` 这个开关是 Day0 stub 加进 `Settings` 的。
没有那个字段时，`getattr(settings, "offline_mode", False)` 恒为假，
**`OFFLINE_MODE=1` 会被静默忽略**——离线不生效，而且一句报错都没有。

`apply_delivery.ps1` 会替你检查这一条（实例化一次 `Settings` 看字段在不在），
缺了就直接拦住并告诉你去哪拿。

## 三步

### ① 解压覆盖

把包内文件按**仓库路径**覆盖到仓库根（包本身镜像了目录结构，直接拖进去即可）。

> 只有两个是**改动**别人的文件：`backend/app/providers/__init__.py`、
> `backend/tests/test_providers.py`。其余全是新增文件。

### ② 一键接入

```powershell
cd <仓库根>
powershell -ExecutionPolicy Bypass -File scripts\offline\apply_delivery.ps1
```

这一步会自动：检查目录结构 → 应用两个补丁 → 跑一遍测试。

想先看看会改什么，加 `-Check`（不写文件）。

**这一步不能跳。** 补丁改的是组长独占的文件（`orchestrator.py`、`main.py` 等），
**不打补丁，离线模式根本用不了**——应用会继续带着哑 key 去连 `api.deepseek.com`，
实测得到 401。

### ③ 下模型 + 启动

```powershell
# 下载推理引擎与模型（约 2GB，走 ModelScope，几分钟）
powershell -ExecutionPolicy Bypass -File scripts\offline\fetch_model.ps1

# 冷启动
powershell -ExecutionPolicy Bypass -File scripts\offline\start.ps1
```

浏览器会自动打开 `frontend/chat.html`。**首次加载模型要 1–2 分钟**，属正常。
那个 PowerShell 窗口要一直开着；关掉用 Ctrl+C，或 `stop.ps1`。

## 出问题先看这里

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报「**Settings 里没有 offline_mode 字段**」 | 仓库没应用 Day0 契约 stub | `git pull`，或找组长要那一版 `config.py` |
| 报「**providers/__init__.py 不是本包的版本**」 | 包没解压覆盖，或覆盖到了错目录 | 确认在仓库根重跑 |
| 报「仓库里缺少这些文件」 | 没在仓库根跑，或包没解压 | `cd` 到仓库根，重新解压覆盖 |
| 报「找不到装了依赖的 Python 解释器」 | venv 不在仓库目录下 | 带一次路径：`-Python <venv>\Scripts\python.exe`，脚本会记住 |
| 报「没找到装了 pytest 的解释器，跳过测试」 | **不是错误** | 补丁已应用好了。想跑测试先 `scripts\run.ps1 -SetupOnly` 建环境 |
| 补丁报「上下文不匹配」 | 目标文件已被别人改过，基线不一致 | `git stash` 后重试；或手工对照补丁里的 `@@` 片段改 |
| 模型下载不动 | 网络 | `fetch_model.ps1` 自动换源（ModelScope → hf-mirror → 原站）；也可 `-ModelUrl` 指内网镜像 |
| 启动后第一句话报 401 | **补丁没打** | 回第 ② 步 |
| 每轮回答很慢（30–110 秒） | CPU 推理，正常 | 首轮最慢（约 1 万 token 的系统提示）；后续轮次有前缀缓存会快些 |

日志在 `scripts/offline/logs/`。

**装好后应该看到**：`apply_delivery.ps1` 跑完是 `219 passed`（未打补丁前是
`198 passed, 1 failed`——那个 failed 就是 `test_alerts.py::test_should_alert_by_risk`，
正是 `0001` 补丁要修的，说明 Day0 stub 本身会让仓库测试变红）。

## ⚠️ 用之前必须知道

**离线链路是通的，但安全兜底有缺口。** 拿项目自己的参考急症用例
（黑便，语料标注 R2b/E1）端到端重复 4 轮：**4/4 定级偏低，4/4 第三层语义复核没触发**。
约 1/5 的概率还会把标签吐在正文中间、末尾续写自我审查残句，用户直接看得见。

**演示 / 录制 / 试用：可以。给真实老人用：先处理这两条。**

1. 离线档把语义复核放宽到全等级（改 `.env.offline`，不改代码）：
   ```ini
   SEMANTIC_CHECK_RISKS=R3,R2b,R2a,R1,R0
   ```
2. 给 `safety_checker.SCENE_KEYWORDS["E1"]` 补「大便发黑」「发黑」「柏油」等口语说法
   （关键词表在 `backend/app/safety/safety_checker.py`，不是 B 的文件）

完整分析见 `docs/offline_delivery_report.md` 第 7 节。

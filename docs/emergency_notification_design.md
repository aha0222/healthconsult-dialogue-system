# 紧急通知家属 · 设计文档（中期检查版）

> **本期只出设计，不写实现代码**（五日计划第 5 天交付物）。
> 这是本阶段风险最高的一项：它对外发消息、涉及老人隐私与他人同意，并且与
> "拔网线离线运行"存在物理层面的矛盾。
>
> 覆盖项：复核闸门 / 渠道选型 / 离线降级 / 冷却去重 / 审计留痕 / 默认关闭 / 误报风险清单。

## 1. 先说清它和现有告警不是一回事

`backend/app/alerts.py` 已经有一套"高危告警"，但它的定位与本项**不同**，不能直接扩展：

| | 现有告警（`alerts.py`） | 紧急通知家属（本项） |
|---|---|---|
| 收件人 | 运维 / 系统 | 家属（非技术用户） |
| 内容 | **刻意脱敏**：只有结构化字段 + 原文字数 + sha256 指纹 | 家属必须看懂发生了什么 |
| 送达要求 | 尽力而为，失败只记日志 | 需要送达确认与升级重试 |
| 去重 | 无（每轮命中都发） | **必须有冷却与去重** |
| 通道 | 单个 webhook URL | 需按可达性与离线情况选型 |

`sanitize_alert()` 的脱敏是**故意的**（`SENSITIVE_FIELDS = ("user_message", "reply")`），
因为日志会长期留存。而家属需要的是"老人出现了什么紧急情况、现在该做什么"。
**两者共用一个 payload 会导致要么泄露原文，要么家属看不懂。** 因此本项需要独立的内容模板
（见第 7 节），不能复用 `sanitize_alert` 的输出。

可以复用的是三样：触发判定 `should_alert()` 的思路、指纹函数 `_fingerprint()`、
以及"推送丢后台线程、失败不阻断对话"的执行模型。

## 2. 触发条件（谁有资格触发）

现有 `ALERT_RISKS=R3,R2b` 对"通知家属"来说**太宽**：R2b 包含不少"需要留意但不需要叫家属"
的情况，每轮都通知会造成狼来了。

建议新增独立配置 `EMERGENCY_NOTIFY_RISKS`（默认 `R3`），并在设计上叠加两个条件：

1. 风险等级 ∈ `EMERGENCY_NOTIFY_RISKS`，**或**命中硬红线兜底（`fallback_used=True`）；
2. **且**第三层语义复核给出了确认结论。

第 2 条是关键：它把通知挂在**已经存在的**第三层复核上，不新增 LLM 调用，也不改变复核范围
（`SEMANTIC_CHECK_RISKS` 本期仍不动）。

### 分级策略（不同等级用不同门槛）

误报与漏报的代价**不是对称的，而且在各等级之间也不同**：

| 场景 | 漏报代价 | 误报代价 | 建议门槛 |
|------|---------|---------|---------|
| E1 急症 / N1·N2 人身安全（R3） | 极高（可能致命） | 家属白跑一趟 | **宁误勿漏**：只要 R3 + 复核不否决就发 |
| M2 心理危机（R2b→R3） | 极高 | 高（老人一句"活得没意思"可能只是感叹，通知家属可能激化家庭矛盾） | **宁漏勿误**：要求语义复核明确确认，且措辞不得直接转述原话 |

> 这一条是整份设计里最需要导师/家属背书的取舍，不要由实现者自行决定。

## 3. 复核闸门（两道）

**第一道：内容判定** —— 关键词/分级（第二层）→ 语义复核（第三层）确认。
复用现有链路，不新增判定逻辑。

**第二道：发送闸门** —— 冷却 + 去重 + 人工兜底：

- **冷却与去重**：对"事件指纹"去重。指纹 = `risk` + 场景 + 会话 ID + 时间窗桶（如 10 分钟）。
  同一指纹在窗口内**只发一次**；窗口外复发允许再发（老人反复出现危机必须能再次通知）。
- **升级穿透**：等级升高时（R2b → R3）不受冷却限制，立即发送。
- **人工兜底**：通知内容里必须包含"如已处理请回复/点击确认"的路径。**没有回执通道的活动
  是单向广播**，家属可能根本没看到。

## 4. 渠道选型

| 渠道 | 离线可用 | 到达率 | 成本 | 隐私/合规 | 说明 |
|------|---------|-------|------|----------|------|
| 局域网推送（家庭网关 / 自建服务） | **可用**（同一 WiFi） | 中（家属需在网内或有常驻端） | 低 | 好（不出家庭网络） | 离线档唯一可行的通道 |
| 短信网关（SMS API） | 不可用 | **最高** | 按条计费 + 需实名报备 | 内容经第三方 | 兜底首选，但需公网 |
| 微信服务号订阅消息 / 企业微信机器人 | 不可用 | 高 | 低 | 经腾讯 | 需家属关注/绑定，适合已入群的场景 |
| 电话外呼（语音网关） | 不可用 | 最强（会响铃） | 最高 | 易被当作骚扰电话 | 仅建议用于最高等级 |

**建议：分级双通道** ——

1. 局域网/自建通道为**首选**（离线也能工作，符合"拔网线演示"的验收路径）；
2. 公网通道（短信或微信）为**兜底**，仅在在线档可用；
3. 两条都失败时，升级为**本地声光提示 + 留痕**（至少让在场的人知道），并记入审计。

> ⚠️ **不要承诺"离线也能通知到家属"**。拔网线时没有任何公网通道可用，这是物理限制。
> 演示与汇报里必须如实说明，否则验收时会被追问。

## 5. 离线降级

三个可选策略，推荐第 2 个：

1. **仅在在线档提供**：离线档明确返回"当前离线，无法通知家属"。简单，但老人独自在家
   恰恰是最需要通知的场景。
2. **本地留痕 + 明确告知（推荐）**：离线档把事件写入本地审计，并在界面上明确提示
   "当前处于离线模式，无法通知家属，建议直接拨打 120 / 联系家属电话"——把兜底责任
   明确交回给在场的人，而不是假装已经通知了。
3. **本地队列 + 恢复后补发**：**不建议作为默认**。延迟送达的急症通知可能比不送达更糟
   （家属会以为刚刚发生）。若要做，必须满足：通知内容带**事件发生时刻**并显著标注
   "延迟送达"，且仅在未超过有效期（如 30 分钟）时补发。

**演示路径要单独说明**：拔网线演示时走路局域网通道是可能的（同一路由器内网通），
但公网通道一定不通。演示脚本应按"局域网通道成功 + 公网通道失败并如实提示"来编排。

## 6. 审计留痕

需要记录（写入本地，不入公网）：

- 事件：等级、场景、发生时刻、指纹、是否经语义复核确认；
- 投递：选用的通道、目标（脱敏后的家属标识）、尝试次数、结果、送达/回执时刻；
- 抑制：被冷却拦下的次数（用来发现"一直在触发但一直没发"的异常）。

**内容脱敏的边界（与 `sanitize_alert` 的关键区别）**：

- 审计日志：沿用 `sanitize_alert` 的做法，不落老人原话与回复正文；
- 发给家属的通知：**允许包含可理解的概括**（如"老人提到胸口疼且持续不缓解"），
  但**不包含**完整原话逐字转述、不包含其他家庭成员隐私、不包含历史对话；
- 两组内容必须分别构造，不允许"把日志 payload 直接发出去"。

## 7. 通知内容模板（需与家属确认）

```
【小暖紧急提醒】{时刻}
老人出现可能需要立即处理的紧急情况：{等级描述，如"胸痛/呼吸困难"}
建议立即：{动作，如"拨打 120 或尽快到场查看"}
{回执提示}：收到请回复"1"
——本消息由小暖自动发出，不能替代专业判断
```

要点：**先给结论与动作，再给细节**；不使用医学诊断措辞（与三层安全一致：不诊断、不承诺）；
必须包含"自动发出、不替代专业判断"的免责表述。

## 8. 默认关闭

新增能力开关 **`EMERGENCY_NOTIFY_ENABLED`，默认 `0`**，与现有的
`VOICE_ENABLED` / `OFFLINE_MODE` / `SPEAKER_DETECT_ENABLED` 同一纪律：

- 关闭时系统行为**完全不变**（与现状逐字节一致）；
- 未交付或关闭时，不得有任何对外网络请求；
- 开启时必须显式配置接收人与通道，缺配置则**启动即报错**，不静默降级
  （参照 `LocalLLM` 的"绝不回退"契约）。

## 9. 误报 / 漏报风险清单

| 风险 | 触发场景 | 缓解 |
|------|---------|------|
| 误报 · 惊吓家属 | 老人转述他人病情、家属自己在描述老人病史，被当作老人本人的急症 | 通知前用**说话人角色**（`speaker_role`）过滤：`family` 的咨询不触发家属通知 |
| 误报 · 狼来了 | 同一事件反复触发通知 | 冷却 + 事件指纹（第 3 节） |
| 误报 · 家庭矛盾 | M2 心理危机中老人一句感叹被原话转述给家属 | M2 走"宁漏勿误"门槛 + 禁止逐字转述 |
| 漏报 · 通道不可达 | 家属手机静音、未关注服务号、短信被拦截 | 双通道 + 回执 + 通道失败升级 |
| 漏报 · 离线 | 拔网线 | 第 5 节的明确告知 + 建议直接拨打 120 |
| 漏报 · 复核否决 | 语义复核误判为合规 | 硬红线兜底（`fallback_used`）**不经过复核**直接放行 |
| 隐私 · 号码泄露 | 家属号码写入代码/仓库 | 只走环境变量；检查 `.gitignore` 与日志脱敏 |
| 隐私 · 未取得同意 | 未经家属与老人同意即启用 | **上线前必须取得书面同意**，并写入部署文档 |

## 10. 与三层安全的关系（不变式）

本项**不改变任何红线判定**，只是把已经判定的高危结果外发。因此：

- 「红线判定与说话人角色无关」这一不变式**继续成立**；
- 说话人角色只用于**过滤误报**（家属的咨询不通知家属本人），不参与风险定级；
- 语义复核范围（`SEMANTIC_CHECK_RISKS`）本期不动。

## 11. 演练要求（上线门槛）

**未经演练不得对真实家属启用。** 演练必须覆盖：

1. 一次真实触发的端到端通知（用**测试号**，不用家属真实号码）；
2. 冷却生效：连续两条同类事件只发一条；
3. 升级穿透：等级升高时冷却不拦截；
4. 通道失败：断开一个通道，确认另一条兜底且留痕；
5. 离线：拔网线，确认走"明确告知"路径而非静默失败；
6. 家属未响应：确认回执缺失时有升级动作。

## 12. 待组长/导师拍板的事项

| # | 事项 | 影响 |
|---|------|------|
| 1 | 渠道选型（局域网优先 + 公网兜底？还是先只做公网短信？） | 决定实现量与演示脚本 |
| 2 | 接收人：通知谁、几个人、是否需要老人知情同意 | 涉及隐私与合规 |

本阶段围绕《第三周主要目标及解决方案》的 6 项任务推进，在已有「前端 + 后端 + skill」三段式架构上，

## 三、分项详述

### 任务 1 · 双维度分级标签体系

每条回复必须同时携带两个维度：

- **风险等级（唯一）**：`R3` 极高 / `R2b` 高 / `R2a` 中高 / `R1` 中 / `R0` 低。
  判定依据不是"是否涉及医疗"，而是"**不加干预是否会受到健康或人身/财产损害**"。
- **场景类别（可交叉，最多 3 个）**：`S1-S4`（症状/用药/慢病/就医）、`M1-M2`（情绪/心理危机）、
  `L1-L4`（饮食/运动/作息/社交）、`E1`（急症）、`N1-N3`（人身/环境/诈骗）、`X1-X2`（闲聊/系统功能）。

实现层单一事实源为 `backend/app/dialogue/taxonomy.py`，规范定义见
`skills/healthconsult-assistant-skill/rules/taxonomy.md`。多场景交叉时风险取最高。

### 任务 2 · 两系统合并 + 资料采集 + 记忆 + 前端展示

- **对话前采集**：新增欢迎流程，采集 10 项资料（称呼、年龄、居住、慢病、用药、过敏史、健康困扰、行动自理、
  紧急联系人、紧急电话），经 `POST /api/profile` 写入后端。
- **用户级权威档案**：SQLite schema 升级到 v5/v6/v7，新增 `users` 表与 `sessions.user_id`，实现跨会话复用。
  紧急联系电话等敏感字段统一脱敏。
- **记忆合并**：`dialogue/profile.py` 负责"采集字段 → 结构化画像"映射、自述画像与对话提炼画像的合并
  （冲突以用户自述为准），`memory.py` 注入唯一一份「【已知信息】」块，并标注"未经医疗核实"。
- **前端展示**：欢迎采集弹窗 + 记忆面板，用户 `user_id` 本地持久化，后续对话自动携带。

### 任务 3 · 人格选型

- 构建 **43 个测试场景**（补齐了原缺失的人身安全 S 类与心理危机 M 类），每场景生成多版人格回复。
- **三种互相独立的方法**交叉评价：场景内强制排序、人工抽检（20–30%）、大模型绝对打分；
  再以 bootstrap 置信区间与置换检验做统计。
- 结论：**温婉邻居型**是唯一在三套方法中都位列前二的人格，选为默认；贴心闺女型三种方法均在末两位，排除。
  （详见 `docs/personality_evaluation_report.md`）

### 任务 4 · 流式输出安全

原前端边生成边输出，遇安全问题会在"已吐出一大段"后才截断，存在隐患。修复方案：

- **高风险输入（R3/R2b）**：全量缓冲、完整校验后再一次性下发，流式期间**不吐任何 delta**，
  命中红线时以安全兜底话术作为最终 `done.reply`。
- **低风险输入**：保留流式实时性，但对已缓冲内容做**增量红线守护**（禁止话术 + 内部规则泄露），
  一旦命中立即停止下发并兜底。
- 前端以 `done.reply` 覆盖已显示正文，保证用户最终看到的一定是安全内容。

### 任务 5 · 语料库建设（组员一）

- **流程**：Kimi 生成 41 条初始语料 → 41 条人工全审 → DeepSeek 以锚点/反例扩展 567 条候选 →
  分层抽样人工审核 → 合并去重定容。
- **规模**：训练语料 **498 条**（`v0.3.0_corpus500.jsonl`），Retriever 标注语料 **569 条**
  （`scene_risk_corpus.jsonl`，由训练语料投影派生，标签 498/498 一致）。
- **覆盖**：16/16 场景、**33/33 (场景,风险) 格子**全覆盖，最大单格偏差 4.2%；平均 1.18 个标签/条。
- **审核**：先写 32 条判据审核清单（格式/标签/安全/人格四类），再全审 41 条 + 分层抽检 176/499 = **35.3%**
  （R3/R2b 与 5 个安全场景 100% 全检）。
- **配套工具**：生成、审核材料、合并去重、分布验收、人工改写回灌、重复 id/交叉标签修复等 12 个脚本。
- **交付文档**：`docs/corpus_build_report.md`、`docs/corpus_review_checklist.md`、`docs/corpus_handoff_notes.md`。

### 任务 6 · 场景/风险识别 + Retriever/Reranker

**两步走设计**：第一步先用关键词/规则快速定风险与场景；第二步按标签检索相似语料注入生成。

- **分类器**（`classifier.py`）：关键词/规则**快路径**（<1ms、0 token）；只在"无命中 / 有歧义 /
  多场景冲突"时调 LLM 兜底分类；兜底时只把 Retriever+Reranker 精排的 Top-N 相似语料作为少样本。
- **Retriever**（`retriever.py`）：嵌入后端可插拔——`local`（sentence-transformers）、
  `api`（OpenAI 兼容）、`hash`（纯 Python，零下载，保证可移植）；支持语料加载与向量缓存。
- **Reranker**（`reranker.py`）：向量相似度 + 字符 n-gram + 关键词/标签命中的混合打分，只保留 Top 2~5。
- **运行时接入**（本阶段补齐）：`orchestrator` 在调用 LLM 前先做快路径预判，并据此
  **路由模型、选择 prompt 形态、注入检索样例**；
  - 典型低风险（R0/R1）使用**精简 prompt**（保留 SKILL.md 规范小节，去掉静态示例，由检索到的真实样例替代）；
  - 高风险（R3/R2b）或歧义时使用**完整 SKILL.md**，且不注入样例，保证安全优先；
  - LLM 漏标时用预判结果兜底补标签。

## 四、技术架构与关键设计

```
前端 frontend/  ──HTTP──▶  后端 backend/  ──system prompt──▶  skill / LLM
                            对话编排 + 安全检查                    │
                            ◀──────── 回复 + 双维度标签 ◀─────────┘
```

- **三层安全**：
  1. `SKILL.md` 作为系统指令，约束行为、自主定级（0 成本）；
  2. 本地关键词快检 `safety_checker`（<1ms，命中硬红线即替换安全话术）；
  3. 高风险 LLM 语义复核 `semantic_checker`（默认对 R3/R2b 开启，离线批量另有 `--mode llm`）。
- **性能与成本**：模型路由（按风险走高/低模型）、回复缓存、token 预算、长会话滚动摘要与长期画像。
- **数据闭环**：线上对话 → 审计表 → 脱敏导出 → 离线质检 → 补规则/补红线用例 → 回归。

## 八、遗留问题与下一步

**已知遗留（不阻塞验收）**
- 初始语料仅用 Kimi、未用 GPT（任务书为"kimi、gpt 等"，非强制；本组无 GPT 调用条件）。
- 语料分布是"频率加权 + 安全过采样"的**合成分布**，需上线后用真实审计数据重算权重。
- 人工审核第二轮（抽检 176 条）有 91 条只记录了结论未逐项展开；若用于论文/结题，建议对高风险层补细粒度评分。

**下一步计划**
1. 用真实线上对话回流数据校准语料分布与评测集。
2. 将检索语料扩展为"用户问题 + 优质回复"对，进一步提升生成质量。
3. 观察运行时分类快路径覆盖率，对误判/歧义样本持续补规则与红线用例。
4. 补充端到端集成测试与多轮越狱/红队用例。
